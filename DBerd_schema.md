# Принципиальная схема базы данных (ERD)

Архитектура хранилища данных спроектирована в реляционной парадигме и приведена к третьей нормальной форме (3NF). Модель исключает транзитивные зависимости и дублирование информации.

Схема содержит **10 сущностей**, из которых 8 представляют физические и осязаемые объекты предметной области:

## Описание таблиц и логических связей

1. **Users** — учетные записи пользователей системы с разделением уровней доступа через поле `Role` (`Listener`, `Speaker`, `Organizer`, `Admin`).
2. **Conferences** — ключевая сущность мероприятий. Хранит временные границы всего события (`StartDate`, `EndDate`), место проведения и ссылку на создателя (`OrganizerId -> Users.Id`).
3. **Halls** — физические помещения и залы проведения. Связаны отношением «многие-к-одному» с `Conferences` (`ConferenceId -> Conferences.Id`) и содержат показатель вместимости (`Capacity`).
4. **Tracks** — тематические направления/секции внутри конкретной конференции (`ConferenceId -> Conferences.Id`).
5. **Speakers** — расширенный профиль докладчика (`UserId -> Users.Id`), содержащий профессиональные регалии, компанию и краткую биографию.
6. **TalkSubmissions** — поданные заявки на доклады. Связывают спикера (`SpeakerId -> Speakers.Id`) с выбранной тематической секцией (`TrackId -> Tracks.Id`). Содержат тезисы и статус прохождения модерации (`Submitted`, `Approved`, `Rejected`).
7. **ScheduleSlots** — финальная сетка программы. Связывает одобренный доклад (`TalkSubmissionId -> TalkSubmissions.Id`) с конкретным залом (`HallId -> Halls.Id`) и фиксирует точное время выступления (`StartTime`, `EndTime`).
8. **Registrations** — связующая таблица регистрации слушателей. Отражает факт записи пользователя (`UserId -> Users.Id`) на конкретную конференцию (`ConferenceId -> Conferences.Id`) со статусом билета.
9. **Partners** — организации-спонсоры мероприятия (`ConferenceId -> Conferences.Id`) с указанием пакета партнерства (`Tier`).
10. **Feedback** — оценки и текстовые отзывы слушателей (`UserId -> Users.Id`) на конкретные выступления в расписании (`ScheduleSlotId -> ScheduleSlots.Id`).
